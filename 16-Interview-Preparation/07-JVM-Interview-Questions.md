# 1. JVM Basics

## 1. What is JVM?

JVM stands for **Java Virtual Machine**.

It is the runtime environment that executes Java bytecode.

```text
Java Source Code
       ↓
    Compiler
       ↓
   Bytecode
       ↓
      JVM
       ↓
Machine-specific execution
```

---

## 2. What is the main purpose of JVM?

The JVM:

- Loads Java classes.
- Verifies bytecode.
- Manages runtime memory.
- Executes bytecode.
- Performs garbage collection.
- Provides runtime services.

---

## 3. Is JVM platform-independent?

The JVM specification is platform-independent, but JVM implementations are platform-specific.

For example, JVM implementations exist for:

```text
Windows
Linux
macOS
```

The same Java bytecode can run on different platforms when an appropriate JVM implementation is available.

---

## 4. Why is Java called platform-independent?

Java source code is compiled into platform-independent bytecode.

```text
Java Code
    ↓
Bytecode
    ↓
JVM for Windows / Linux / macOS
```

The JVM handles platform-specific execution.

---

## 5. Is JVM platform-independent or platform-dependent?

The distinction is important:

```text
Bytecode
→ platform-independent


JVM implementation
→ platform-dependent
```

---

## 6. What is JDK?

JDK stands for:

```text
Java Development Kit
```

It provides tools required to develop Java applications.

It includes:

```text
JVM
JRE/runtime components
Compiler
Development tools
```

---

## 7. What is JRE?

JRE traditionally refers to the runtime environment required to run Java applications.

Conceptually:

```text
JRE
→ JVM
→ Runtime libraries
```

Modern Java distributions generally do not ship a separate end-user JRE in the same way older Java versions did.

---

## 8. What is the difference between JDK, JRE and JVM?

```text
JDK
→ Development environment


JRE
→ Runtime environment concept


JVM
→ Executes bytecode
```

A simplified relationship is:

```text
JDK
 └── Runtime components
      └── JVM
```

---

## 9. What is bytecode?

Bytecode is the intermediate instruction format generated by the Java compiler.

A Java source file:

```text
Test.java
```

is compiled into:

```text
Test.class
```

The `.class` file contains bytecode.

---

## 10. Which tool compiles Java source code?

The Java compiler:

```text
javac
```

Example:

```text
javac Test.java
```

produces:

```text
Test.class
```

---

## 11. Which component executes Java bytecode?

The JVM executes or otherwise processes Java bytecode.

The execution engine can interpret bytecode and use JIT compilation to produce native machine code for frequently executed code.

---

## 12. Why doesn't Java directly compile everything to machine code?

Java uses a combination of interpretation and JIT compilation.

This allows the JVM to:

```text
Run portable bytecode
+
Optimize frequently executed code at runtime
```

---

The Class Loader Subsystem loads class definitions into the JVM.

# 3. Class Loader

## 19. What is a Class Loader?

A Class Loader loads class definitions into the JVM when they are required.

---

## 20. What are the main phases of class loading?

The class-loading process can be viewed as:

```text
Loading
Linking
Initialization
```

Linking includes:

```text
Verification
Preparation
Resolution
```

---

## 21. What happens during Loading?

During loading, the JVM obtains the binary representation of a class and creates the corresponding class representation in memory.

---

## 22. What happens during Verification?

Verification checks that the loaded class's bytecode conforms to JVM constraints and is structurally valid.

---

## 23. What happens during Preparation?

The JVM allocates memory for class-level static fields and assigns their default values.

---

## 24. What happens during Resolution?

Symbolic references in the class's runtime constant pool may be resolved into direct references.

Resolution can occur lazily depending on the JVM implementation.

---

## 25. What happens during Initialization?

Class initialization executes static initialization code, including static field initializers and static blocks, in the required order.

Example:

```java
class Test {

    static int x = 10;

    static {
        System.out.println("Initialized");
    }
}
```

---

## 26. What are Bootstrap, Platform and Application Class Loaders?

Modern Java class loading commonly involves:

```text
Bootstrap Class Loader
Platform Class Loader
Application Class Loader
```

The exact implementation and hierarchy details are JVM-specific.

---

## 27. What is Bootstrap Class Loader?

It loads core Java platform classes.

In modern Java, these classes are provided through the platform modules.

The bootstrap loader is implemented by the JVM rather than as an ordinary Java class-loader object.

---

## 28. What is Platform Class Loader?

The Platform Class Loader loads platform classes that are not loaded by the bootstrap loader.

It replaced the older terminology of the Extension Class Loader in Java 9.

---

## 29. What is Application Class Loader?

The Application Class Loader loads application classes and classes available through the application class path/module path.

---

## 30. What is Parent Delegation?

Under the parent-delegation model, a class loader generally asks its parent loader to load a class before attempting to load the class itself.

Conceptually:

```text
Application
     ↓
Platform
     ↓
Bootstrap
```

---

## 31. Why is parent delegation used?

It helps:

```text
Prevent duplicate loading
Protect core classes
Maintain class-loading consistency
```

For example, application code should not replace core platform classes simply by defining a class with the same fully qualified name.

---

## 32. Can a class be loaded twice?

A class can be loaded by different class loaders, producing distinct runtime class identities.

Class identity is associated with:

```text
Fully qualified class name
+
Defining class loader
```

---

## 33. What is ClassNotFoundException?

It is a checked exception that can occur when code explicitly attempts to load a class by name and the class cannot be found.

Example:

```java
Class.forName("abc.Test");
```

If the class cannot be located, `ClassNotFoundException` can occur.

---

## 34. What is NoClassDefFoundError?

`NoClassDefFoundError` is an `Error` that can occur when the JVM or class loader tries to use a class definition that was available or expected at compile time but cannot be successfully found or initialized at runtime.

---

## 35. ClassNotFoundException vs NoClassDefFoundError?

```text
ClassNotFoundException
→ checked exception
→ commonly occurs during explicit dynamic class loading


NoClassDefFoundError
→ Error
→ JVM cannot successfully load a required class definition at runtime
```

---

# 4. Runtime Data Areas

## 36. What are JVM Runtime Data Areas?

They are memory areas used during JVM execution.

Important areas include:

```text
Heap
JVM Stacks
Method Area
PC Register
Native Method Stacks
```

---

## 37. Which JVM memory area is shared among threads?

Commonly shared areas include:

```text
Heap
Method Area
```

The JVM specification defines these as shared runtime data areas.

---

## 38. Which JVM memory areas are thread-private?

Each thread has its own:

```text
PC Register
JVM Stack
Native Method Stack
```

---

## 39. What is the Program Counter Register?

Each JVM thread has a PC register.

It identifies the current JVM instruction being executed by that thread, with special handling when the thread is executing a native method.

---

## 40. What is JVM Stack?

Each thread has its own JVM stack.

It stores stack frames associated with method invocations.

---

## 41. What is a Stack Frame?

A stack frame is created for each method invocation.

A frame can contain:

```text
Local variables
Operand stack
Reference to runtime constant pool
Other implementation-specific information
```

---

## 42. What happens when a method is called?

A new stack frame is created for that method invocation and pushed onto the current thread's JVM stack.

---

## 43. What happens when a method finishes?

Its stack frame is removed from the current thread's JVM stack.

---

## 44. What is StackOverflowError?

`StackOverflowError` can occur when a thread's JVM stack cannot accommodate additional frames.

A common cause is uncontrolled recursion.

Example:

```java
static void test() {

    test();
}
```

---

## 45. What is OutOfMemoryError?

`OutOfMemoryError` occurs when the JVM or a particular runtime data area cannot provide the required memory, subject to the JVM's implementation and configuration.

---

## 46. StackOverflowError vs OutOfMemoryError?

```text
StackOverflowError
→ typically associated with excessive stack-frame usage


OutOfMemoryError
→ memory allocation cannot be satisfied in a required area
```

---

# 5. Heap Memory

## 47. What is Heap memory?

The heap is the runtime data area from which memory for class instances and arrays is allocated.

---

## 48. Is heap shared between threads?

Yes.

The heap is shared among JVM threads.

---

## 49. Where are objects stored?

Objects and arrays are allocated in the heap.

The exact physical layout and optimization can vary by JVM implementation.

---

## 50. Where are local primitive variables stored?

Local variables belonging to a method invocation are represented in that method's stack frame.

However, JVM/JIT implementations can optimize storage internally, so the simplified stack/heap model should not be treated as a strict physical-memory map.

---

## 51. Where are object references stored?

A reference used as a local variable is part of the method's frame.

A reference stored as an instance field is part of the object's state in the heap.

---

## 52. Is the String pool inside heap?

The String pool is maintained by the JVM as part of runtime memory associated with the heap.

String literals are interned and stored in the string pool.

---

## 53. What is the String Pool?

The String Pool is a JVM-managed pool of interned String objects.

It allows identical interned strings to share the same String object.

Example:

```java
String a = "Java";
String b = "Java";
```

Typically:

```text
a == b
→ true
```

because both refer to the same interned literal.

---

## 54. What happens with `new String()`?

Example:

```java
String s =
    new String("Java");
```

The string literal `"Java"` is interned, while `new String(...)` creates a distinct String object.

Therefore, the reference created by `new` is normally different from the pooled literal reference.

---

## 55. What is a memory leak in Java?

A memory leak occurs when objects are no longer logically needed but remain reachable, preventing garbage collection.

Example causes include:

```text
Unbounded static collections
Forgotten listeners
Improper caches
Long-lived references
```

---

## 56. Can Java have memory leaks despite garbage collection?

Yes.

Garbage collection removes unreachable objects.

If an unwanted object is still reachable, the GC considers it eligible to remain.

---

# 6. Method Area and Metaspace

## 57. What is Method Area?

The Method Area is a JVM runtime data area that stores per-class structures such as:

```text
Class metadata
Runtime constant pool
Method information
Field information
```

The exact implementation is JVM-specific.

---

## 58. What is Metaspace?

In HotSpot, Metaspace is the native-memory-based implementation used for class metadata starting with Java 8.

It replaced the older PermGen implementation.

---

## 59. What is PermGen?

PermGen stands for:

```text
Permanent Generation
```

It was used by older HotSpot JVMs for class metadata and related data.

It was removed in Java 8 and replaced by Metaspace.

---

## 60. Metaspace vs PermGen?

```text
PermGen
→ older HotSpot design
→ JVM-managed fixed-style region


Metaspace
→ Java 8+
→ uses native memory for class metadata
```

---

## 61. Can Metaspace run out of memory?

Yes.

Excessive class loading or class-loader leaks can cause:

```text
OutOfMemoryError: Metaspace
```

---

## 62. What is Runtime Constant Pool?

Each class or interface has a runtime constant pool containing information derived from the class file's constant pool.

It includes symbolic information used by the JVM, such as:

```text
Class references
Method references
Field references
String constants
```

---

# 7. Garbage Collection

## 63. What is Garbage Collection?

Garbage Collection is the automatic process of reclaiming heap memory occupied by objects that are no longer reachable.

---

## 64. Who performs Garbage Collection?

The JVM's Garbage Collector performs garbage collection.

The exact algorithm depends on the selected or default collector and JVM implementation.

---

## 65. When is an object eligible for garbage collection?

An object becomes eligible when it is no longer reachable from GC roots.

---

## 66. What are GC Roots?

GC roots are objects or runtime references from which reachability is traced.

Common examples include:

```text
Live thread references
Static references
JNI references
Active stack references
```

The exact root set depends on the JVM implementation.

---

## 67. Can we force Garbage Collection?

No.

You can request GC:

```java
System.gc();
```

but the JVM is not required to perform collection immediately or at all because of that request.

---

## 68. What does `finalize()` do?

Historically, `finalize()` provided a mechanism for cleanup before an object was reclaimed.

It has been deprecated for removal since Java 9 and should not be used for resource management.

---

## 69. Why should `finalize()` not be used?

Because finalization is:

```text
Unpredictable
Slow
Not guaranteed to run promptly
Problematic for resource management
```

Use mechanisms such as:

```text
try-with-resources
AutoCloseable
```

for resource cleanup.

---

## 70. What is a Minor GC?

A Minor GC generally refers to garbage collection focused on the young generation in generational collectors.

The exact behavior depends on the collector.

---

## 71. What is a Major GC?

The term "Major GC" is not used with one universally fixed meaning across all collectors.

It is often used to describe collection involving older generations, but terminology can vary.

---

## 72. What is Full GC?

A Full GC generally involves a broader collection of heap regions and can have significant application pauses depending on the collector and circumstances.

The exact behavior is collector-specific.

---

## 73. What is Stop-The-World?

Stop-The-World means application threads are paused while the JVM performs a particular operation.

Garbage collectors can have STW phases.

---

## 74. What is a GC pause?

A GC pause is a period during which application threads are stopped for garbage-collection work.

Modern collectors attempt to reduce pause times, but the actual behavior depends on the collector and workload.

---

## 75. What is generational garbage collection?

Generational GC is based on the observation that many objects become unreachable soon after creation.

The heap is therefore managed in generations such as:

```text
Young Generation
Old Generation
```

Collectors may use different terminology and layouts.

---

## 76. What is the Young Generation?

It is the region where newly allocated objects are commonly managed in generational collectors.

It is typically divided conceptually into:

```text
Eden
Survivor spaces
```

---

## 77. What is Eden?

Eden is the allocation region where newly created objects are commonly allocated in generational collectors.

---

## 78. What are Survivor spaces?

Survivor spaces hold objects that survive young-generation collections.

They are commonly represented as:

```text
S0
S1
```

---

## 79. What is Old Generation?

The Old Generation generally contains objects that have survived enough collection cycles or otherwise meet the collector's criteria for promotion or placement there.

---

## 80. What is G1 GC?

G1, or Garbage-First Garbage Collector, is a region-based garbage collector designed to provide predictable pause-time goals while managing large heaps.

---

## 81. What is ZGC?

ZGC is a low-latency garbage collector designed to keep pause times very small, including for large heaps.

---

## 82. What is Serial GC?

Serial GC uses a single thread for garbage-collection work.

It can be suitable for certain smaller or resource-constrained applications.

---

## 83. What is Parallel GC?

Parallel GC uses multiple threads for garbage-collection work and is designed around throughput.

---

# 8. JIT and Execution Engine

## 84. What is Interpreter?

The interpreter executes bytecode instruction by instruction.

---

## 85. What is JIT Compiler?

JIT stands for:

```text
Just-In-Time Compiler
```

It compiles frequently executed bytecode into native machine code at runtime.

---

## 86. Why is JIT needed?

Repeatedly interpreting hot code can be slower than executing optimized native code.

JIT compilation can:

```text
Detect hot code
Compile it
Optimize it
Reuse compiled machine code
```

---

## 87. What is hot code?

Hot code is code that executes frequently enough for the JVM to consider optimizing it through JIT compilation.

---

## 88. What is the difference between interpreter and JIT compiler?

```text
Interpreter
→ executes bytecode instructions


JIT
→ compiles frequently executed code
→ produces optimized native machine code
```

---

## 89. Does JVM only interpret bytecode?

No.

Modern JVMs generally combine:

```text
Interpretation
+
JIT compilation
```

---

## 90. What is native machine code?

Native machine code consists of processor-specific instructions that can be executed directly by the CPU.

---

## 91. What is tiered compilation?

Tiered compilation combines different levels of execution and compilation to balance:

```text
Fast startup
+
Good runtime performance
```

It allows the JVM to gather execution information before applying more expensive optimizations.

---

## 92. What is deoptimization?

The JVM can sometimes reverse or invalidate an optimization when runtime assumptions used by the optimization stop being valid.

The code can then fall back to a less optimized execution path.

---

# 9. JVM and Java Memory

## 93. What is the Java Memory Model?

The Java Memory Model, or JMM, defines rules for how threads interact through memory.

It specifies concepts such as:

```text
Visibility
Ordering
Atomicity
Happens-before relationships
```

---

## 94. What is happens-before?

A happens-before relationship guarantees that certain actions performed by one thread become visible to another thread according to the Java Memory Model.

Examples include relationships established by:

```text
synchronized
volatile
Thread.start()
Thread.join()
```

and certain concurrency utilities.

---

## 95. What is the difference between stack and heap?

```text
Stack
→ thread-specific
→ contains method frames


Heap
→ shared
→ contains objects and arrays
```

---

## 96. Why is stack memory faster than heap memory?

The simplified explanation is that stack allocation and frame management are highly structured and associated with method execution.

However, actual JVM implementations use optimizations such as escape analysis and scalar replacement, so the simplistic statement "stack is always faster than heap" is not universally accurate.

---

## 97. What happens when a local variable is created?

Its representation is associated with the current method's stack frame.

For object references, the reference is stored in the frame while the referenced object is generally allocated in the heap.

---

## 98. What happens when an object is created?

The JVM allocates memory for the object, normally in the heap, and returns a reference to it.

The exact allocation mechanism can be optimized by the JVM.

---

## 99. What happens when a method is called?

A stack frame is created for the invocation.

The frame contains information needed to execute that method.

---

## 100. What happens when the method returns?

Its frame is removed from the current thread's JVM stack.

Objects referenced by that frame become eligible for GC if no other references keep them reachable.

---

# 10. JVM and Java Memory

## 101. What is escape analysis?

Escape analysis is a JVM optimization technique used to determine whether an object or reference escapes a method or thread.

The JVM can use this information for optimizations such as:

```text
Scalar replacement
Lock elimination
Allocation optimization
```

---

## 102. Can an object be allocated without actually going to the heap?

The Java specification does not require every object to physically reside in a particular memory region.

A JIT compiler may optimize an allocation away or represent an object differently when safe.

Therefore, "every object is always physically on the heap" is an oversimplification.

---

## 103. What is class unloading?

Class unloading is the removal of class metadata from the JVM when the class and its defining class loader are no longer reachable and the JVM determines unloading can occur.

It is particularly relevant to application servers, plugin systems, and dynamically generated classes.

---

## 104. When can a class be unloaded?

A class can generally be unloaded when:

```text
Its defining class loader is unreachable
+
Its class objects and related instances are no longer reachable
```

The JVM decides whether and when class unloading occurs.

---

## 105. Why are class-loader leaks dangerous?

If a class loader remains reachable unintentionally, classes loaded by it may also remain reachable.

This can prevent class metadata from being unloaded and can eventually cause:

```text
Metaspace
OutOfMemoryError
```

---

# 11. Tricky JVM Questions

## 106. Is JVM the same as JRE?

No.

```text
JVM
→ executes bytecode


JRE
→ runtime environment concept containing JVM and runtime libraries
```

---

## 107. Is JDK the same as JVM?

No.

```text
JDK
→ development kit


JVM
→ runtime execution engine/environment
```

---

## 108. Is Java completely platform-independent?

Java bytecode is designed to be platform-independent.

The JVM implementation is platform-specific.

---

## 109. Is JVM completely platform-independent?

No.

JVM implementations are built for specific operating systems and processor architectures.

---

## 110. Can two JVMs run on the same machine?

Yes.

Multiple independent JVM processes can run simultaneously on the same operating system.

---

## 111. Is heap memory shared by all threads?

Yes, within the same JVM.

---

## 112. Is stack memory shared by all threads?

No.

Each JVM thread has its own JVM stack.

---

## 113. Where are static variables stored?

Static fields are associated with the class rather than individual objects.

Their exact runtime memory representation is JVM-implementation-dependent.

The common conceptual model associates class metadata and static state with the class-level runtime area rather than with individual object instances.

---

## 114. Where is the class metadata stored?

In HotSpot, class metadata is primarily stored in Metaspace, which uses native memory.

The JVM specification itself does not require a specific physical implementation called "Metaspace."

---

## 115. Can garbage collection collect static objects?

Yes, if the static reference itself or its defining class loader becomes unreachable.

A static reference associated with a live class can keep the referenced object reachable.

---

## 116. Can `System.gc()` guarantee garbage collection?

No.

It is only a request or suggestion to the JVM.

---

## 117. Can an object be garbage collected while it is still referenced?

Normally, an object reachable from GC roots is not eligible for collection.

JVM optimizations can determine that a reference will never be used again before the lexical scope ends, but an object cannot be reclaimed while it remains semantically reachable according to GC analysis.

---

## 118. What is the difference between memory leak and memory overflow?

```text
Memory leak
→ unwanted objects remain reachable


OutOfMemoryError
→ JVM cannot satisfy a required memory allocation
```

A memory leak can eventually lead to an OutOfMemoryError.

---

## 119. Can Java have stack memory leaks?

The usual concept of a memory leak applies mainly to heap or class-loader reachability.

Excessive recursion can instead cause:

```text
StackOverflowError
```

---

## 120. What happens if `main()` finishes?

The JVM does not necessarily terminate immediately.

It terminates when there are no remaining non-daemon threads.

---

## 121. Can JVM execute code without a `main()` method?

Yes, depending on the context and Java version.

A Java program launched as a traditional application needs an appropriate entry point, but JVMs can execute code through other mechanisms such as agents, tools, containers, or programmatic invocation.

---

## 122. Why is `main()` static?

The traditional Java launcher needs an entry point that can be invoked without first creating an instance of the containing class.

---

## 123. What happens first: class loading or object creation?

The class must be sufficiently loaded, linked, and initialized as required before the object can be instantiated.

Class initialization is triggered when required by the JVM's initialization rules.

---

## 124. Does creating an object always initialize the class?

If the class has not already been initialized, creating an instance normally triggers class initialization before the constructor executes.

---

## 125. What is class initialization order?

For a class being initialized, initialization follows the JVM's specified rules involving:

```text
Superclasses
Superinterfaces with initialization requirements
Static field initializers
Static blocks
```

The exact order follows Java Language Specification rules.

---

## 146. What is GC Root?

```text
A runtime reference from which object reachability is traced.
```

## 147. What is heap?

```text
Shared runtime area for objects and arrays.
```

---

## 148. What is stack?

```text
Thread-private area containing method invocation frames.
```

---

## 149. What is Method Area?

```text
JVM runtime area for class-level structures
such as metadata and runtime constant pools.
```

## 150. What is JMM?

```text
Java Memory Model
→ defines rules for memory visibility,
ordering, and synchronization between threads.
```
