# 1. Java Basics

## 1. What is Java?

Java is a high-level, class-based, object-oriented programming language designed to be portable across platforms through the Java Virtual Machine (JVM).

---

## 2. What are the main features of Java?

Important features include:

- Object-oriented
- Platform independent
- Robust
- Secure
- Multithreaded
- Portable
- Architecture neutral
- Automatic garbage collection
- Rich standard library

---

## 3. Why is Java platform independent?

Java source code is compiled into bytecode.

The bytecode runs on a JVM specific to each operating system.

```text
Java Source Code
       ↓
    javac
       ↓
    Bytecode
       ↓
      JVM
   ↙    ↓    ↘
Windows Linux macOS
```

The same bytecode can run on different platforms as long as a compatible JVM exists.

---

## 4. Why is Java called "write once, run anywhere"?

Because Java source code is compiled into platform-independent bytecode, which can execute on JVM implementations available for different operating systems.

---

## 5. Is Java purely object-oriented?

No.

Java has primitive data types such as:

```text
int
char
boolean
double
```

Therefore, Java is not considered a purely object-oriented language.

---

## 6. Is Java compiled or interpreted?

Java uses both compilation and runtime execution.

```text
Source Code
    ↓
Compiler
    ↓
Bytecode
    ↓
JVM
    ↓
Interpreter/JIT
    ↓
Machine Code
```

The JVM can interpret bytecode and use the JIT compiler to compile frequently executed code into native machine code.

---

## 7. What is bytecode?

Bytecode is the intermediate instruction format generated by the Java compiler.

It is stored in `.class` files and executed by the JVM.

---

## 8. What is the `.class` file?

A `.class` file contains JVM bytecode generated by the Java compiler.

Example:

```text
Test.java
   ↓
javac Test.java
   ↓
Test.class
```

# 2. JVM, JDK and JRE

## 9. What is JVM?

JVM stands for Java Virtual Machine.

It executes Java bytecode and provides the runtime environment required to run Java applications.

---

## 10. What is JDK?

JDK stands for Java Development Kit.

It contains tools required to develop Java applications, including the Java compiler and runtime components.

---

## 11. What is JRE?

JRE traditionally refers to the runtime environment containing the JVM and libraries needed to run Java applications.

Modern JDK distributions are generally the primary installation used for Java development, and separate JRE distributions are no longer the standard distribution model in the same way they were historically.

---

## 12. Difference between JVM, JRE and JDK?

```text
JVM
→ Runs bytecode

JRE
→ JVM + runtime libraries

JDK
→ Development tools + runtime components
```

Conceptually:

```text
JDK
 └── Runtime Environment
       └── JVM
```

---

## 13. What is JIT compiler?

JIT stands for Just-In-Time compiler.

It identifies frequently executed bytecode and can compile it into native machine code at runtime to improve performance.

---

## 14. What is the difference between JVM and JIT?

```text
JVM
→ Complete runtime environment

JIT
→ Component/technique within the JVM's execution system
   that compiles suitable bytecode to native code
```

---

# 3. Variables and Data Types

## 15. What are primitive data types in Java?

Java has eight primitive types:

```text
byte
short
int
long
float
double
char
boolean
```

---

## 16. What is the difference between primitive and reference types?

Primitive variables directly represent primitive values.

Reference variables hold references to objects.

Example:

```text
int
→ primitive

String
→ reference type
```

---

## 17. What is the default value of an instance variable?

For instance variables, Java provides default values.

Examples:

```text
int       → 0
boolean   → false
reference → null
```

Local variables do not receive automatic default values and must be initialized before use.

---

## 18. What is type casting?

Type casting means converting a value from one type to another compatible type.

Two major categories are:

```text
Widening
Narrowing
```

---

## 19. What is widening casting?

Widening converts a smaller compatible primitive type into a larger compatible type.

Example:

```text
int → long
```

It is generally performed automatically.

---

## 20. What is narrowing casting?

Narrowing converts a larger type into a smaller type.

Example:

```text
double → int
```

It generally requires explicit casting.

---

## 21. What is variable shadowing?

Shadowing occurs when a variable in a narrower scope has the same name as a variable in an outer scope.

Example:

```java
class Test {

    int value = 10;

    void show() {

        int value = 20;

        System.out.println(value);
    }
}
```

The local variable shadows the instance variable inside the method.

---

# 4. Operators and Control Flow

## 22. What is the difference between `==` and `equals()`?

`==` compares primitive values or reference identity.

`equals()` is a method intended for logical equality and can be overridden by classes.

Example:

```java
String a = new String("Java");
String b = new String("Java");
```

```text
a == b
→ false
```

```text
a.equals(b)
→ true
```

---

## 23. What are short-circuit operators?

The short-circuit logical operators are:

```text
&&
||
```

With `&&`, if the first condition is false, the second may not be evaluated.

With `||`, if the first condition is true, the second may not be evaluated.

---

## 24. Difference between `break` and `continue`?

```text
break
→ terminates the loop/switch

continue
→ skips the current loop iteration
```

---

## 25. What is the difference between `while` and `do-while`?

`while` checks the condition before executing the body.

`do-while` executes the body at least once before checking the condition.

---

# 5. OOP Fundamentals

## 26. What are the four pillars of OOP?

```text
Encapsulation
Inheritance
Polymorphism
Abstraction
```

---

## 27. What is encapsulation?

Encapsulation means bundling data and behavior together while controlling access to the object's internal state.

A common implementation uses private fields and public methods.

---

## 28. What is inheritance?

Inheritance allows a class to acquire accessible properties and behavior from another class.

Example relationship:

```text
Child IS-A Parent
```

---

## 29. What is polymorphism?

Polymorphism means one interface/reference can represent different underlying implementations.

Two commonly discussed forms in Java are:

```text
Compile-time polymorphism
→ method overloading

Runtime polymorphism
→ method overriding
```

---

## 30. What is abstraction?

Abstraction focuses on exposing essential behavior while hiding implementation details.

Java provides abstraction primarily through:

```text
Abstract classes
Interfaces
```

---

## 31. What is the difference between abstraction and encapsulation?

```text
Abstraction
→ hides implementation complexity

Encapsulation
→ controls access to internal state/implementation
```

---

# 6. Classes, Objects and Constructors

## 32. What is a class?

A class is a blueprint/type definition that describes state and behavior for objects.

---

## 33. What is an object?

An object is an instance of a class.

It has identity and can contain state and behavior defined by its class.

---

## 34. What is a constructor?

A constructor is a special member used to initialize a newly created object.

It:

- Has the same name as the class
- Has no return type
- Is invoked during object creation

---

## 35. Can a constructor be inherited?

No.

Constructors are not inherited.

---

## 36. Can a constructor be overridden?

No.

Constructors are not inherited, so they cannot be overridden.

---

## 37. Can a constructor be overloaded?

Yes.

A class can have multiple constructors with different parameter lists.

---

## 38. What is a default constructor?

If a class declares no constructor, the compiler can provide a no-argument constructor.

Once you declare a constructor yourself, the compiler does not automatically add that default constructor.

---

## 39. Can a constructor be `static`?

No.

Constructors belong to object creation and are not inherited or invoked as static members.

---

# 7. Inheritance and Polymorphism

## 40. Does Java support multiple inheritance?

Java does not support multiple inheritance of classes.

A class can implement multiple interfaces.

---

## 41. Why doesn't Java support multiple inheritance of classes?

Multiple class inheritance can introduce ambiguity, such as the diamond problem.

Java avoids this complexity by allowing one direct superclass while supporting multiple interfaces.

---

## 42. What is method overloading?

Method overloading means defining multiple methods with the same name but different parameter lists in the same class or inheritance context.

Example:

```java
void add(int a, int b) {
}

void add(int a, int b, int c) {
}
```

---

## 43. What is method overriding?

Method overriding occurs when a subclass provides its own implementation of an inherited overridable method.

---

## 44. Can a static method be overridden?

No.

Static methods are hidden rather than overridden.

---

## 45. Can a private method be overridden?

No.

A private method is not inherited by subclasses in the normal overriding sense.

---

## 46. Can a final method be overridden?

No.

A `final` method cannot be overridden.

---

## 47. What is dynamic method dispatch?

Dynamic method dispatch is the mechanism by which an overridden instance method is selected at runtime based on the actual object.

Example concept:

```text
Parent reference
      ↓
Child object
      ↓
Child's overridden method
```

---

# 8. Abstraction and Encapsulation

## 48. What is an abstract class?

An abstract class is a class declared with `abstract` that cannot be directly instantiated.

It can contain:

```text
Abstract methods
Concrete methods
Fields
Constructors
Static members
```

---

## 49. What is an interface?

An interface defines a contract that implementing classes agree to follow.

Modern interfaces can contain:

```text
Abstract methods
Default methods
Static methods
Private methods
Constants
```

---

## 50. Abstract class vs interface?

```text
Abstract class
→ can maintain instance state
→ can have constructors
→ single class inheritance


Interface
→ defines a contract
→ a class can implement multiple interfaces
→ supports default/static/private methods
```

---

## 51. Can an abstract class have a constructor?

Yes.

The constructor can initialize the part of the object belonging to the abstract superclass when a subclass object is created.

---

## 52. Can an interface have a constructor?

No.

Interfaces are not instantiated as classes.

---

# 9. `static`, `final` and Access Modifiers

## 53. What is `static`?

`static` indicates that a member belongs to the class rather than to individual instances.

It can be used with:

```text
Fields
Methods
Nested classes
Initialization blocks
```

---

## 54. What is a static variable?

A static variable belongs to the class and is shared among instances of that class.

---

## 55. What is a static method?

A static method belongs to the class rather than an object.

It can be called using the class name.

---

## 56. Can a static method access instance variables directly?

No.

A static method does not have an implicit `this` reference.

It needs an object reference to access instance members.

---

## 57. What is `final`?

`final` restricts modification depending on where it is used.

```text
final variable
→ cannot be reassigned

final method
→ cannot be overridden

final class
→ cannot be extended
```

---

## 58. What are access modifiers in Java?

Four access levels are commonly discussed:

```text
private
default/package-private
protected
public
```

---

## 59. What is the most restrictive access modifier?

`private`.

A private member is directly accessible only within its declaring class.

---

# 10. Strings

## 60. Why is String immutable?

A String object cannot be changed after creation.

Immutability provides benefits such as:

```text
String pool sharing
Security
Thread-safety benefits
Hash-code stability
Predictable behavior
```

Operations that appear to modify a String create or return another String instead.

---

## 61. What is String Pool?

The String Pool is a JVM-managed area associated with interned String objects.

String literals can be reused rather than creating a separate String object for every identical literal.

---

## 62. String vs StringBuilder?

```text
String
→ immutable


StringBuilder
→ mutable
→ generally preferred for repeated string modification
   in single-threaded code
```

---

## 63. StringBuilder vs StringBuffer?

```text
StringBuilder
→ generally not synchronized
→ generally preferred for single-threaded use


StringBuffer
→ synchronized
→ legacy thread-safe mutable string class
```

---

## 64. What is `intern()`?

`intern()` returns a canonical representation of a String from the string pool.

If an equivalent interned string does not already exist, the string can be added to the pool.

---

## 65. Difference between `equals()` and `equalsIgnoreCase()` for String?

```text
equals()
→ case-sensitive comparison


equalsIgnoreCase()
→ ignores case differences
```

---

# 11. Arrays

## 66. What is an array?

An array is a fixed-size indexed data structure that stores elements of the same array type.

---

## 67. Can array size be changed after creation?

No.

An array has a fixed length after creation.

---

## 68. Can an array store primitives?

Yes.

Example:

```text
int[]
double[]
char[]
```

---

## 69. Can an array store objects?

Yes.

Example:

```text
String[]
Employee[]
```

---

## 70. What is the difference between array length and String length?

For an array:

```text
array.length
```

For a String:

```text
string.length()
```

`length` is a field for arrays, while `length()` is a method for String.

---

# 12. Exception Handling

## 71. What is an exception?

An exception is an event represented by an object that disrupts the normal flow of program execution.

---

## 72. Checked vs unchecked exceptions?

```text
Checked exceptions
→ checked by the compiler


Unchecked exceptions
→ RuntimeException and its subclasses
```

Checked exceptions generally must be caught or declared.

---

## 73. What is the difference between `throw` and `throws`?

```text
throw
→ explicitly throws an exception object


throws
→ declares that a method may propagate specified exceptions
```

---

## 74. What is `finally`?

`finally` is a block associated with exception handling that is generally used for cleanup code.

It normally executes whether an exception occurs or not, subject to abnormal termination scenarios such as JVM termination.

---

## 75. Can we have `try` without `catch`?

Yes, if it has a `finally` block.

Example concept:

```text
try
    ↓
finally
```

---

## 76. What is try-with-resources?

Try-with-resources automatically closes resources that implement `AutoCloseable`.

It is commonly used for:

```text
Files
Streams
Readers
Database resources
```

---

# 13. Collections

## 77. What is the Collection Framework?

The Java Collections Framework provides interfaces, implementations, and algorithms for storing and manipulating groups of objects.

Major interfaces include:

```text
List
Set
Queue
Deque
Map
```

`Map` is part of the Collections Framework but does not extend `Collection`.

---

## 78. ArrayList vs LinkedList?

```text
ArrayList
→ dynamic array
→ fast random access


LinkedList
→ linked-node structure
→ efficient insertion/removal when the relevant position/node is already known
```

---

## 79. ArrayList vs Vector?

```text
ArrayList
→ generally unsynchronized
→ modern general-purpose list


Vector
→ synchronized legacy collection
```

---

## 80. HashSet vs TreeSet?

```text
HashSet
→ hash-based
→ no guaranteed sorted order


TreeSet
→ tree-based
→ maintains sorted order
```

---

## 81. HashMap vs TreeMap?

```text
HashMap
→ hash-based
→ no guaranteed sorted key order


TreeMap
→ tree-based
→ sorted by keys
```

---

## 82. HashMap vs Hashtable?

```text
HashMap
→ generally unsynchronized
→ allows one null key and null values


Hashtable
→ legacy synchronized map
→ does not permit null keys or values
```

---

## 83. What is the difference between List, Set and Map?

```text
List
→ ordered collection
→ duplicates generally allowed


Set
→ unique elements


Map
→ key-value mappings
→ keys are unique within a map
```

---

## 84. How does HashMap work internally?

Conceptually:

```text
key
 ↓
hashCode()
 ↓
hash processing
 ↓
bucket/index
 ↓
key comparison
 ↓
value
```

Hash collisions are handled internally by the implementation.

Modern HashMap implementations can use tree structures for heavily collided buckets under certain conditions.

# 14. Generics

## 85. What are Generics?

Generics allow classes, interfaces, and methods to operate on parameterized types while providing compile-time type checking.

Example:

```text
List<String>
```

---

## 86. What is type erasure?

Java implements generics primarily through type erasure.

Generic type parameters are not generally reified at runtime in the same way as languages with reified generics.

---

## 87. What is `<?>`?

`<?>` is an unbounded wildcard.

Example:

```text
List<?>
```

It means a List of some unknown type.

---

## 88. What is PECS?

PECS means:

```text
Producer Extends
Consumer Super
```

Use:

```text
? extends T
```

when a structure primarily produces values of type `T`.

Use:

```text
? super T
```

when a structure primarily consumes values of type `T`.

---

# 15. Multithreading

## 89. What is a thread?

A thread is an independent path of execution within a process.

---

## 90. Process vs thread?

```text
Process
→ independent execution environment


Thread
→ execution unit within a process
```

Threads within the same process generally share process resources.

---

## 91. What is synchronization?

Synchronization coordinates concurrent access to shared mutable state.

It can provide mutual exclusion and memory-visibility guarantees.

---

## 92. What is `volatile`?

`volatile` tells the JVM that reads and writes of the variable must follow the volatile memory-visibility and ordering rules.

It does not make compound operations such as `count++` atomic.

---

## 93. What is deadlock?

Deadlock occurs when multiple threads wait indefinitely for resources held by one another.

Typical example:

```text
Thread A
→ holds Lock 1
→ waits for Lock 2

Thread B
→ holds Lock 2
→ waits for Lock 1
```

---

## 94. What is ExecutorService?

`ExecutorService` provides a higher-level API for submitting and managing asynchronous tasks using executor-managed threads.

---

# 16. Java Memory and JVM Concepts

## 95. Stack vs Heap?

Conceptually:

```text
Stack
→ method execution frames
→ local variables/references
→ per-thread


Heap
→ objects and arrays
→ shared among threads
```

The JVM specification defines runtime data areas precisely, and implementation details can vary.

---

## 96. What is Garbage Collection?

Garbage Collection automatically identifies objects that are no longer reachable and reclaims their memory.

---

## 97. Can we force Garbage Collection?

No.

You can request garbage collection using:

```text
System.gc()
```

but the JVM is not required to perform a collection because of that request.

---

## 98. What is `finalize()`?

`finalize()` was an old mechanism associated with object cleanup before garbage collection.

It has been deprecated for removal and should not be used for resource management.

Modern Java should use explicit resource management such as:

```text
try-with-resources
AutoCloseable
```
